# 受け取り口の設置（事務所で1回だけ・約10分）

店員さんのスマホで作ったポップを、**法人の Google アカウントのドライブ**へ自動で集めるための受け取り口です。
費用はかかりません（Google Apps Script の無料枠）。

```
店員さんのスマホ ──共有・保存と同時に自動で送る──▶ 受け取り口（このフォルダの Code.gs）
                                                      └▶ ドライブ「青果ポップ 成果物」フォルダ
```

## 1. スクリプトを作る

1. **法人の Google アカウント**でログインしたブラウザで <https://script.google.com/> を開く
2. 「新しいプロジェクト」→ 左上の「無題のプロジェクト」を **青果ポップ 受け取り口** に変える
3. 最初からある `コード.gs` の中身を全部消し、このフォルダの **`Code.gs` の中身を全部貼り付けて** 保存（Ctrl+S）

## 2. 合言葉を決めて入れる

1. PC のブラウザで <https://yashima840.github.io/SeikaPop/tools/collector/link.html> を開く
   （ファイルをダブルクリックで直接開くと動かない。`start.bat` を起動して <http://127.0.0.1:8765/tools/collector/link.html> でもよい）
2. 「新しい合言葉を作る」→「合言葉をコピー」（言葉3つと3桁の数。例 `tomato-negi-kaki-482`。口で伝えられる）
3. スクリプトの画面の左の ⚙（プロジェクトの設定）→ 一番下「スクリプト プロパティ」→「スクリプト プロパティを追加」
   - プロパティ: `PASSCODE`
   - 値: コピーした合言葉
   - 「スクリプト プロパティを保存」

合言葉は `Code.gs` に書かないこと（GitHub に上げるとき公開されてしまうため）。

## 3. ウェブアプリとして公開する

1. 右上「デプロイ」→「新しいデプロイ」→ 種類の選択（⚙）で「ウェブアプリ」
2. 次のとおりにして「デプロイ」
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**（スマホからログイン無しで送るため。合言葉が無いと受け付けない）
3. 「アクセスを承認」→ 法人アカウントを選ぶ →「このアプリは Google で確認されていません」と出たら
   「詳細」→「青果ポップ 受け取り口（安全ではないページ）に移動」→「許可」
   （自分で作ったスクリプトなので確認されていないだけ。許可するのはこのアカウントのドライブへのファイル作成）
4. 表示された **ウェブアプリの URL**（`https://script.google.com/macros/s/…/exec`。法人用のアカウントだと `https://script.google.com/a/macros/会社のドメイン/s/…/exec`）をコピー
5. その URL をブラウザで開いて「この画面が出れば設置できています」と出れば完了

## 4. アプリに受け取り口の URL を入れる（店ごとに1回）

`js/collect.js` の `BUILT_IN_COLLECTOR_URL` を 3 の URL にして公開版へ上げる。
URL だけでは送れない（合言葉が要る）ので、GitHub で見えても困らない。

## 5. 店員さんに合言葉を伝える

1. 合言葉を口頭・朝礼などで伝える（**店の外の人には教えない**）
2. 店員さんの操作: アプリの ⚙ 設定 →「みんなで使える場所」に**名前と合言葉**を入れて「合言葉で設定する」
   （iPhone のホーム画面のアイコンでも Safari でも同じ。1回入れれば覚える）
3. 「事務所に届くことを確かめました」と出れば、その端末は設定済み。合言葉が違えば「合言葉が違います」と出て、入れない

前の**設定用リンク**も使える（`link.html` の下半分で作る。リンクには合言葉が入っている）。合言葉の欄にリンクを貼り付けても設定できる。

## 集まったもの

ドライブの「**青果ポップ 成果物**」フォルダに、次の名前で溜まります。

```
トマト_熊本県_田中_20261026-0830_1a2b3c.jpg    … 出した画像
トマト_熊本県_田中_20261026-0830_1a2b3c.json   … 作り直し用のデータ（写真・価格・デザインの選び方）
```

- 名前は **商品名_産地_作った人_日時_印**（ドライブを「名前」で並べると商品ごとにまとまる。産地が無ければその欄は無い。日時と印は同じ名前にならないためのもの）。
  前の形（`20261026-0830_田中_トマト_1a2b3c`）のファイルもそのまま一覧に出る
- 同じポップを2回出した（LINE と Instagram など）ときは、前のファイルはゴミ箱へ移り**最新の1件**になります（30日はゴミ箱から戻せます）
- 広告は画像だけです
- **どの端末からでも呼び出せる**: アプリのはじめの画面「📂 保管したポップから作る」に、`.json` と `.jpg` がそろっている分が商品名順（同じ商品は産地 → 新しい順）に並ぶ
  （500 件まで）。タップすると同じ中身（写真も）で今日のポップを作り、価格・産地の確認の印を付けるまで出せない（レギュラーと同じ）。
  呼び出したポップを出すと、**元とは別の1件**として入る（元のファイルは書き換えない）。要らなくなったものはドライブで消す
  （`.jpg` と `.json` の両方。片方だけ残っても一覧には出ない）
- 一覧の見本は写真ストックと同じしくみで「青果ポップ 成果物の見本（消しても作り直されます）.json」にまとめて持つ
- フォルダの名前は変えても構いません（場所は ID で覚えています）。フォルダを消すと、次に届いたときに作り直します

## 写真ストック（どの端末からでも呼び出せる写真）

同じ受け取り口で、ドライブの「**青果ポップ 写真ストック**」フォルダを写真の置き場にします（費用はかかりません）。

```
PC の担当 ──ドライブのフォルダへ写真をドラッグ──▶ 青果ポップ 写真ストック ◀──「📤 この写真をストックに入れる」── 現場のスマホ
                                                        │
                       どの端末でも 編集画面の「📦 ストックから」で一覧 → タップでそのポップの写真になる
```

- **使い始める**（すでに受け取り口を設置済みのとき）: このフォルダの新しい `Code.gs` を貼り直して、
  「デプロイ」→「デプロイを管理」→ ✎ →「バージョン: 新バージョン」→「デプロイ」（URL は変わらない＝アプリの直しも要らない）。
  その後どれかのスマホで「📦 ストックから」を開くと、ドライブに「青果ポップ 写真ストック」フォルダができる
  （先に PC で同じ名前のフォルダを作っても使われない。アプリが作ったフォルダへ入れること）
- **一覧の見本（軽くするしくみ）**: アプリは写真と一緒に 200px の小さい見本（1枚 数KB）を送り、受け取り口はそれをドライブの
  「青果ポップ 写真ストックの見本（消しても作り直されます）.json」1つにまとめて持つ（マイドライブの一番上にできる）。
  一覧を開いたときは、ここからまとめて返すので、ドライブが作る重い見本（PNG で1枚 数十KB）を1枚ずつ取り出すより速く、通信も少ない。
  ドライブへ直接入れた写真など見本が無いものは、最初に一覧を開いた端末が縮めて預け直す（以後はどの端末にも軽い見本が届く）。
  このファイルは消しても写真は無くならない（見本が順に作り直される）。
- **PC の担当が入れる・直す**: 作業場の「写真ストックの管理」でまとめて送る（縮めて・見本も付けて送るので、一覧が軽い）。
  同じ画面の「今のストック」で、名前を変える・ゴミ箱へ移す（30日はドライブのゴミ箱から戻せる）。
  または、ドライブでそのフォルダを開き、写真をドラッグして入れる。**ファイル名が一覧の名前**になる（例: `トマト 大玉.jpg`）。
  形は **JPEG・PNG・WebP**、1枚 20MB まで。iPhone の HEIC は Android で開けないので一覧に出ない（JPEG にしてから入れる）
- **現場で入れる**: 編集画面の「📤 この写真をストックに入れる」。補正前の元の写真が `商品名_名前_日時_印.jpg` で入る
  （アプリでは「商品名（名前）」と出る）。電波が無いときは端末に控えて、つながったときに送る
- **消す・名前を変える**: ドライブで直接（アプリからは消せない。誤って消されないように）
- 一覧は新しい順に 500 枚まで。合言葉を知っている端末だけが読める。読めるのはこのフォルダの中だけ

## 困ったとき

| 起きたこと | 対処 |
|---|---|
| スマホに「合言葉が違います」 | `PASSCODE` が変わった・打ち間違い。今の合言葉を ⚙ 設定 →「みんなで使える場所」で入れ直す |
| 合言葉が漏れたかもしれない | `PASSCODE` を新しい合言葉に変える → 全員に伝えて入れ直してもらう（前の合言葉の端末からは届かなくなる） |
| `Code.gs` を直した（PC から上げる） | clasp（Google の公式ツール）で上げられる。法人アカウントで `clasp -u seikapop login` 済みなら、`bash tools/collector/deploy.sh "説明"` で下の手順をまとめて行う（番号の付いたデプロイを全部更新）。手で行うなら `tools/collector` で `clasp -u seikapop push --force` → `clasp -u seikapop list-deployments` で番号の付いたデプロイ（`@1` など。`@HEAD` ではない方）の ID を見て `clasp -u seikapop update-deployment <その ID> -d "説明"`（URL は変わらない）。`.clasp.json`（スクリプト ID）と `appsscript.json` は店ごとなので Git に入れない |
| `Code.gs` を直した（画面で） | 「デプロイ」→「デプロイを管理」→ ✎ →「バージョン: 新バージョン」→「デプロイ」（URL は変わらない）。**「新しいデプロイ」にすると URL が変わり、`BUILT_IN_COLLECTOR_URL` の直しと公開が要る** |
| 「📦 ストックから」「📂 保管したポップから作る」で「受け取り口が古い版です」 | 新しい `Code.gs` を貼り直して「新バージョン」でデプロイ（上の「写真ストック」） |
| PC で入れた写真が一覧に出ない | HEIC など開けない形か 20MB 超え（一覧の上に「出していません n 枚」と出る）。JPEG にして入れ直す |
| スマホに「送れていないものが n 件」 | 電波が戻ればアプリを開いたときに送り直す。理由はスマホの ⚙ 設定 →「みんなで使える場所」に出る |

## 限り

- スクリプト プロパティに「どのポップをどのファイルに置いたか」を1件約100文字で控えています。
  上限（500KB）まで約4,000件。超えそうになったら作り替えが要ります（試用の段階では届かない量）
- 届いたものは法人アカウントのドライブにだけあり、外からは見えません
